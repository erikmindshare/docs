---
title: "Display Types"
description: "The Display Type column picks the input control for each question — text, choices, ratings, uploads, signatures, and structural rows like Section, Screen and Terminal Screen."
---


Every row in the **Questions** sheet has a **Display Type** — the kind of control the respondent
sees and the kind of value it collects. You pick it from the dropdown in the `Display Type` column
(the allowed values live on the **DisplayTypes** tab).

In the AutoSurvey question editor, open a question and go to **Answer & options**. The
**Display type** control is a grid of icon tiles in groups: Text, Number, Date & time, Choice,
Rating & scale, Rich input, and Content & structure. Hover over a tile, or move keyboard focus to
it, to see one sentence about what the type does. Some tiles show a friendly name: **Yes / No** is
`YesNo`, **Checkboxes** is `Checkbox` with an Option Set, and **Ending** is `Terminal Screen`. The
stored value does not change. You make a new screen with **+ Add screen**, not with a tile, and a
Section's type is locked.

<Note>
  Some display types need a list of choices — set that with the **Option Set** column. See
  [Option Sets](/concepts/option-sets). Per-type tuning (star count, slider range, upload limits,
  consent wording) is set with the **Display Properties** column. See
  [Display Properties](/concepts/display-properties).
</Note>

## Text

| Display Type | Collects | Option Set? |
| --- | --- | --- |
| `ShortText` · `Text` | Single line of text | No |
| `Text Area` | Multiple lines (short) | No |
| `Text Area (Long)` · `LongText` *(aliases `Long Text`, `LongTextArea`)* | Long free text | No |
| `Text Area (Rich)` | Formatted (rich) text | No |
| `Masked Text` *(alias `Text (Encrypted)`)* | Masked text input | No |

`ShortText` and `Text` are separate display types that render the same single-line control — as are
`Text Area (Long)` and `LongText` for long free text. Use whichever name reads better in your sheet;
both are kept as written.

<Warning>
  `Masked Text` masks the input in the survey, but the answer is stored as plain text unless the
  mapped reporting field is itself an encrypted Salesforce field. Don't use it to collect regulated
  secrets expecting encryption at rest. See [Security & Privacy](/admin/security-and-privacy).
</Warning>

## Numbers, dates & contact info

| Display Type | Collects | Option Set? |
| --- | --- | --- |
| `Number` | A whole or decimal number (for example `6.5`) | No |
| `Percent` | A percentage | No |
| `Currency` | A money amount (set the ISO code in Display Properties) | No |
| `Date` | A date | No |
| `DateTime` | A date and time | No |
| `Time` | A time of day | No |
| `Email` / `Phone` / `URL` | Contact info, with light format validation | No |
| `YesNo` *(aliases `Boolean`, `yes no`, `true/false`)* | A single yes/no tick box | No |
| `Checkbox` *(no Option Set)* | A single yes/no tick box | No |

A `YesNo` question and a `Checkbox` question with no Option Set show one tick box beside the
question text, with the help text under it. In the question editor, use the **Yes / No** tile for
this. The **Checkboxes** tile is for a list of options.

## Choice questions (need an Option Set)

These render your **Option Set** as the choices:

| Display Type | UX | Select |
| --- | --- | --- |
| `Picklist` *(aliases `Dropdown`, `Choice`, `Select`)* | Dropdown | One |
| `Radio` | Radio buttons | One |
| `Likert5` *(alias `Likert`)* | A 1–5 agreement scale | One |
| `MultiPicklist` | Multi-select picklist | Many |
| `Multi` | Multi-select | Many |
| `Checkbox` *(with an Option Set)* | Checkbox group ("select all that apply") | Many |
| `RadioHorizontal` · `RadioVertical` · `CheckboxHorizontal` · `CheckboxVertical` | Legacy spellings of `Radio` and `Checkbox` with a fixed layout | One / Many |

<Tip>
  `Likert5` ships as its own display type with a 1–5 range. You can also build any other scale as a
  reusable Option Set (e.g. a 7-point agreement list) referenced from a `RadioHorizontal` or
  `Matrix` question — use whichever is closer to what you want.
</Tip>

<Note>
  Set the option layout with the `orientation` Display Property on a `Radio` or `Checkbox`
  question. In the question editor, this is the **Layout** control beside the display type:
  **Auto**, **Vertical** or **Horizontal**. **Auto** clears the property, and the survey then
  decides from how many options there are. The four split spellings (`RadioHorizontal`,
  `RadioVertical`, `CheckboxHorizontal`, `CheckboxVertical`) still work, but the tile grid does not
  offer them. When you change the Layout of a question stored with a split spelling, the editor
  changes its type to `Radio` or `Checkbox`.
</Note>

On a choice question you can also:

* **Shuffle the options** for each respondent with the `randomize` Display Property (`random`, or
  `flip` for the reverse order to half of respondents). Each respondent keeps their own order. Add
  `randomizeIgnoreLast` to keep the last option at the bottom.
* **Make an option exclusive** on a checkbox question with the `exclusive` Display Property — for
  example `exclusive=NON` for a "None of these" option with the value `NON`. Ticking it clears the
  other ticks, and ticking another option clears it.

See [Display Properties](/concepts/display-properties).

## Ratings & ordering

| Display Type | Collects | Notes |
| --- | --- | --- |
| `NPS` | 0–10 Net Promoter scale | No Option Set needed; powers the Suite Insights NPS tile |
| `Star` | 1..N stars | Set the count (and half-stars) in Display Properties |
| `Slider` *(alias `Scale`)* | A number on a track | Set min / max / step in Display Properties |
| `Ranking` | The respondent's preferred **order** of the options | **Needs an Option Set.** Drag to reorder |

<Note>
  A `Ranking` answer is stored as one answer record **per option**, carrying that option's 1-based
  position. Reports read the position, not a single field.
</Note>

## Uploads & signatures

| Display Type | Collects | Option Set? |
| --- | --- | --- |
| `FileUpload` | File attachments, stored as Salesforce Files | No |
| `Signature` | A drawn signature, stored as an image | No |

Tune uploads with `multiple`, `maxSizeMb` and `accept` in Display Properties:

```json
{"multiple": true, "maxSizeMb": 10, "accept": ".pdf,.png"}
```

<Warning>
  **A `maxFiles` property is accepted, but not currently enforced.** Setting it is not an error —
  it just doesn't limit anything yet: neither the upload control nor the save rejects extra files.
  The only file-count limit that is enforced is a fixed cap of **25 files per submission**. If a
  particular count matters to you, say so in the question's help text. `multiple`, `maxSizeMb` and
  `accept` all work as described.
</Warning>

<Note>
  The reporting field for a `FileUpload` question holds a **filename summary**, not the file. The
  files themselves are attached to the submission record like any other Salesforce file, and follow
  your org's sharing and storage rules. A `Signature` is stored as an image in the answer itself.
</Note>

## Consent

| Display Type | Collects | Option Set? |
| --- | --- | --- |
| `Consent` | An explicit agreement, with the terms and version recorded | No |

Set the wording and the link in Display Properties:

```json
{"agreeText": "I agree to the", "termsLabel": "Privacy Notice",
 "termsUrl": "https://example.com/privacy", "consentVersion": "2026-08"}
```

<Warning>
  **A `Consent` question is always mandatory.** Unlike an ordinary yes/no question — where "no" is a
  valid answer — an unticked consent blocks submission whether or not you mark the row Required.
  There is no way for a respondent to finish without agreeing.
</Warning>

<Tip>
  `consentVersion` is stored with the response, so you can tell which wording someone agreed to after
  you've changed it. Set it before you launch, not after.
</Tip>

## Structure & layout

| Display Type | Purpose |
| --- | --- |
| `Screen` | Starts a new page in the survey |
| `Section` | Groups questions inside a screen under a heading or card |
| `DisplayText` *(alias `Label`)* | Static text shown to the respondent — instructions, headings. Shown as a heading; set `textSize` to `body` to show it at the size of question text |
| `Image` | A picture shown to the respondent. Collects no answer. It has no Required, Scoring or Default Value. In the question editor, set the picture with **Image URL** in the **Content** group |
| `Matrix` *(alias `Radio Matrix`)* | A "multiple-choice grid": `Matrix` rows sharing one column Option Set. On a one-question-per-screen survey, set `oneRowPerScreen` to show each row on its own screen. See [Matrix programs](/concepts/matrix-programs) |
| `Terminal Screen` | **Ends the survey here**, and records whether they finished or were screened out |

### Terminal Screens — ending early and screening out

A `Terminal Screen` is an end page. Its `status` Display Property records *why* the survey ended:

| Value | Recorded outcome |
| --- | --- |
| `complete` *(default)* | The respondent finished |
| `screened_out` | They didn't qualify |

Put a **Show If** rule on the Terminal Screen row to control when a respondent lands there — the
same rule syntax as any other row. That is how you screen someone out:

| Question | Display Type | Display Properties | Show If |
| --- | --- | --- | --- |
| Thanks — you're not eligible | `Terminal Screen` | `{"status": "screened_out"}` | `q_role = "Contractor"` |

<Tip>
  You don't have to write this JSON by hand. In the AutoSurvey editor, open the screen and set
  **Screen kind** to **Ending — completes the survey** or **Ending — screens out (disqualifies)**.
  In Google Sheets, the **Display Properties Builder** in the sidebar offers an **"Ends the survey
  as"** choice on Terminal Screen rows — pick **Completed** or **Screened out** and it writes the
  value for you.
</Tip>

<Warning>
  If you do author the JSON yourself, write it exactly as shown: the values are lower-case with an
  underscore, and only `complete` and `screened_out` are accepted — anything else stops the import.
</Warning>

<Note>
  A `screened_out` terminal screen may only carry display content — `DisplayText`, `Image` and `Section` rows.
  Putting an answerable question on it stops the import (`TERMINAL_SCREEN_HAS_ANSWERABLE_CONTENT`): arriving at it is what finalizes the submission, so it cannot also collect
  the answer.
</Note>

<Note>
  Screened-out responses are still saved, and are recorded with a distinct outcome. You keep the
  record of who was turned away and why.
</Note>

## Aliases and unrecognized values

The importer normalizes common variants to the canonical name — `Long Text` / `LongTextArea` → `LongText`,
`Dropdown` / `Choice` / `Select` → `Picklist`, `Percentage` → `Percent`, `Radio Matrix` → `Matrix`,
`Boolean` / `true/false` → `YesNo`, `Label` → `DisplayText`.

If you type a value nothing recognizes, **two different checks can catch it, at two different
moments** — and they are not checking the same list:

| Where | Code | What it checks |
| --- | --- | --- |
| The **sidebar** in Google Sheets | `INVALID_DISPLAY_TYPE` | Whether the value appears **exactly** on **your sheet's Display Types tab** — alias spellings don't pass |
| **Import into Salesforce** | `UNKNOWN_DISPLAY_TYPE` | Whether **AutoSurvey can actually draw a control** for it |

Both stop the import. They agree on an untouched sheet — but they are different lists, so if you
edit the **DisplayTypes** tab they can disagree in either direction: a row you added there passes
the sidebar and fails the import, and a name you deleted fails the sidebar even though the import
would have accepted it.

When you make a new survey in AutoSurvey, the **Review** step runs the import check before it
creates anything. It lists each refused row, and **Create** stays off until you fix or remove the
row.

<Note>
  The two checks also treat a recognized-but-non-canonical spelling differently. The **import**
  normalizes it and moves on. The **sidebar** blocks it: an alias spelling isn't exactly on the
  Display Types tab, so it draws a blocking `INVALID_DISPLAY_TYPE` — alongside an auto-fixable
  `NON_CANONICAL_DISPLAY_TYPE` hint that offers to rewrite it to the canonical name. Accept the fix
  and both go away: `Long Text` becomes `LongText`.
</Note>

<Warning>
  The import's check is the one that matters in the end, and deliberately so: a question with a
  display type nothing can draw renders **no input control at all**. If that question is Required, the
  respondent can never finish it. The error names the offending value and lists every accepted
  display type.
</Warning>
