Open the **App Launcher** and choose **AutoSurvey**. Eleven tabs — six of them AutoSurvey's own,
and one of those is where you'll spend almost all your time.

## Surveys — where you build

**The entry point.** Everything starts here: create a survey, open one you're working on, edit its
questions, and release it.

The page has two parts:

* **The survey list** on the left. Its heading is the name of the current workspace — a folder for
  surveys. Use it to switch workspace, and **New Survey** to start a survey. The list toggle at the
  top left of the survey header hides or shows the list.
* **The open survey** on the right, with one header and five tabs.

The survey header carries the same controls on every tab:

| | |
| --- | --- |
| **Try it** | Run the survey yourself, as yourself or as a guest on your site. Test runs are not counted in results |
| **Release** | Appears when there is something to release — **Release v1** on a new survey, **Release N changes** later. Beside it, the release state (for example *draft* or *live*) opens release history, the public link, and close or reopen |
| **Validate** | Checks the questions. On the Questions tab only |
| **Sheet sync** | Google Sheet sync, an advanced option for bulk edits. Its dot shows the sync state |
| **⋯** | The one menu for everything else: rename, move to another workspace, sheet actions, repair reporting, **Stop accepting responses…**, **Reopen collection…** and delete |

The five tabs:

| | |
| --- | --- |
| **Questions** | Build and edit the questions, in **List** or **Preview**. Changes save as a draft until you release |
| **Design** | How the survey looks — themes, palettes, brand, welcome and ending copy. See [Themes & Design](/concepts/themes-and-design) |
| **Send** | How people get the survey — the public link and QR code, in-app, site members and email |
| **Results** | The responses that came back, reporting health, and a link to CX Analytics |
| **Settings** | How it runs, answers, scoring and alerts, data (including the reporting object), and the questions sheet |

A survey that stops accepting responses shows as **Closed**. **Reopen collection…** in the **⋯**
menu opens it again.

<Tip>
  If you are ever unsure where to start, start here. Every other tab in this list is something you
  reach *after* a survey exists.
</Tip>

## Setup — where an admin gets the org ready

One-time configuration and the health checks that tell you it worked: connections, permissions,
public survey access, CAPTCHA. It also holds the **Show survey suites** switch, which lets one
survey have more than one form. See the [Setup Home Guide](/admin/setup).

## Responses — where responses land

A browser over every response, with filters and paging. Open an individual response to read what
someone actually answered.

<Note>
  This is the response-by-response view. For reporting *across* responses, use ordinary Salesforce
  reports — see [Data & Reporting](/concepts/data-and-reporting).
</Note>

## CX Analytics — where you check how you're doing

A cross-survey view built on your scored questions, with period-over-period movement.

Filter by metric (**NPS**, **CSAT**, **CES**), date range, survey, form, channel, audience, wave or
country, and see how each has moved against the previous period.

<Note>
  CX Analytics reads the score **stamped onto each submission**, so it only shows questions you
  marked with a **Metric Type**. If a survey looks empty here, that is usually why — see
  [The Questions Sheet](/concepts/questions-sheet).
</Note>

<Tip>
  A survey's own **Results** tab links straight through to this tab already filtered to that survey,
  so you rarely need to set the filters by hand.
</Tip>

## Theme Library — where the org's themes live

The org-level shelf: which themes and palettes this org has, which are available to pull down, and a
one-click way to get the latest.

<Note>
  **The Library stocks the shelf; the Design tab styles a survey.** Pulling a theme here makes it
  available in the org. Adopting one happens on a survey's own **Design** tab. See
  [Themes & Design](/concepts/themes-and-design).
</Note>

## My Surveys — where you take a survey

Your own inbox: the surveys *you* have been assigned, split into to-do and completed, with a button
to start or continue each one.

<Tip>
  Worth opening even if you only build surveys. It is exactly what the people you send surveys to
  see, and the fastest way to notice that an assignment did not land the way you expected.
</Tip>

## The standard tabs

The app also carries **Campaigns**, **Leads** and **Contacts** — used by campaign distribution — and
**Reports** and **Dashboards**, because AutoSurvey's reporting is ordinary Salesforce reporting.
