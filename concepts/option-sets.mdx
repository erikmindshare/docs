title: "Option Sets"

An **Option Set** is a named, reusable list of choices (e.g. `YesNo`, `Likert5`, `Satisfaction`).
Define it once on the **Option Sets** tab, then point any choice question at it with the
**Option Set** column on the Questions sheet.

<Note>
  Choice [display types](/concepts/display-types) — `Picklist`, `Radio`, `MultiPicklist`, the
  `Checkbox` group types, `Likert5`, `Matrix` and `Ranking` — **require** an Option Set. If one is
  missing, import is blocked with `MISSING_OPTION_SET`.
</Note>

## The Option Sets tab

Each row is one choice in a set.

| Column | Required | Meaning |
| --- | --- | --- |
| `Option Set` | Yes | The set name. Repeat it on every row that belongs to the set |
| `Label` | Yes | The text the respondent sees |
| `Key` | No | The stable value that gets stored. Defaults to the Label if blank. Also accepted as `Value` |
| `Score` | No | The number this answer contributes when the question is scored. On a single-choice question and on a grid row, the chosen option's score is saved as the answer's numeric value, and the Results tab shows its average and range. A multi-choice question does not use it |
| `Is Default` | No | Pre-selects this option when the question first appears. Also accepted as `Is_Default`. On a multi-choice question, every default option is ticked. On a single-choice question, the first default option in the order is selected. A `Default Value` on the question row wins over it |
| `Order` | No | The position of this choice in the list |
| `Image URL` | No | An absolute image URL, to render this choice as a picture. Also accepted as `Image_URL`. Not in the shipped template — add the column yourself |

**Example — a 5-point agreement scale, scored 1–5:**

| Option Set | Label | Key | Score | Order |
| --- | --- | --- | --- | --- |
| `Agreement5` | Strongly disagree | 1 | 1 | 1 |
| `Agreement5` | Disagree | 2 | 2 | 2 |
| `Agreement5` | Neutral | 3 | 3 | 3 |
| `Agreement5` | Agree | 4 | 4 | 4 |
| `Agreement5` | Strongly agree | 5 | 5 | 5 |

The `Key` is what gets stored in the question's reporting column, so a numeric reporting column
receives 1–5 while respondents read the labels. The `Score` gives the same numbers to scoring.

Then on the Questions sheet, set `Option Set` = `Agreement5` for any question that uses it.

<Tip>
  **`Label` is what the respondent reads; `Key` is what you report on.** Setting an explicit `Key`
  means you can reword a label later without breaking existing responses or the Show If rules that
  compare against it.
</Tip>

## Edit an option set in AutoSurvey

You can also edit option sets in the AutoSurvey question editor. Open a choice question and go to
**Answer & options**:

* Pick a set in **Option set**, or choose **+ Create a new option set…** and name it.
* Under the picker, the editor says if the set is shared (**Shared by N questions.**) or
  **Used by this question only.**, and shows the first options.
* **Edit options** (or **Edit shared options** for a shared set) opens the option set editor in a
  dialog. Each option has a **Label** and a **Value**. The Value follows the label until you type a
  value of your own. Drag a row, or use **Move up** and **Move down**, to change the order.
  **Show questions** lists the questions that use a shared set.
* Open **Scoring & default** in the dialog to set a **Score** and **Is default** for each option.
* **Customize for this question** copies the whole set under a new name. Only this question moves
  to the copy. The other questions keep the shared set.

Saved changes are a draft. Respondents see them after you **Release** the survey.

## Picture choices

Give an option an **`Image URL`** and the whole question renders as a grid of image cards instead of
a list. The shipped template doesn't include this column — add it to the Option Sets tab yourself,
headed `Image URL` or `Image_URL`, and the import picks it up by header name.
It works on any `Radio` or `Checkbox` question — there is no separate picture display type,
and the stored answer is unchanged, so reporting, piping and Show If rules all behave exactly as
they did.

| Option Set | Label | Key | Image URL |
| --- | --- | --- | --- |
| `Packaging` | Slim box | slim | `https://…/slim.png` |
| `Packaging` | Tall box | tall | `https://…/tall.png` |

<Note>
  One image is enough to switch the question to a grid — options without one still render, just
  without a picture. The grid also overrides the `orientation` Display Property, because a picture
  grid already wraps its own columns.
</Note>

<Warning>
  **An `Image URL` longer than 250 characters is silently truncated on import**, which breaks the
  link and leaves the card blank. Signed or heavily parameterised URLs run long — shorten them, or
  host the image at a stable short path.
</Warning>

<Note>
  **If the cards are blank on a public survey, check your org's Content Security Policy.** A public
  survey runs on an Experience Cloud site that you create and secure, and a site can be set to
  refuse images from hosts it does not trust. AutoSurvey ships trusted-site entries for Google
  hosts only, so an image on your own CDN may need one adding in **Setup → CSP Trusted Sites**.
  Whether your site enforces this depends on the security level you chose for it, so test one
  picture question on the public link before you build a survey around images.
</Note>

## Rules

* **Labels must be unique within a set** (case-insensitive) — duplicates are blocked
  (`DUPLICATE_OPTION_LABEL`).
* Every option row needs both an `Option Set` name and a `Label`.
* A label can be at most 251 characters; a set name at most 79 — validation blocks at 252 and 80.
  Saved labels are additionally trimmed to 250 characters, silently.
* A name in a question's `Option Set` column that has no rows on the Option Sets tab blocks the
  import with `MISSING_OPTION_SET_DEFINITION` — usually a rename or a trailing space.

<Warning>
  **A `Key` (or, with no `Key`, a Label) that isn't a number, on a question whose reporting column
  is numeric, loses the answer.** The suite imports, the survey runs, every respondent can answer — and the value is
  written **empty** to that column while the write still reports success. AutoSurvey warns about
  this at import (`NON_NUMERIC_OPTION_VALUE_FOR_NUMERIC_COLUMN`), and that warning is the only
  notice you get. If a set feeds a numeric question, keep its keys numeric.
</Warning>

<Note>
  A choice question whose set has no rows imports with a warning (`OPTIONLESS_CHOICE_QUESTION`) and
  is then shown as "no options configured" and skipped. Its Required flag is ignored, so respondents
  aren't trapped — but nobody can answer it either.
</Note>

## Reuse

The point of Option Sets is reuse: define `Likert5` once and reference it from a dozen questions, or
from every row of a [matrix](/concepts/matrix-programs). Editing the set changes every question that
uses it. To change the options of one question only, use **Customize for this question** (see
above).

## "Other (please specify)"

The choice key **`__OTHER__`** is reserved. Don't add it to the Option Set yourself — instead turn on
an Other option with the `allowOther` token in the question's
[Display Properties](/concepts/display-properties), or with the **Allow “Other”** switch in the
question editor. When selected, it reveals a free-text box.
Import blocks any Option Set row whose key resolves to `__OTHER__`.

<Note>
  The **Option Set** column on the Questions tab does one unrelated job: on a Text Area question it
  carries the height, written as `lines:10`. That is the only case where the column holds something
  other than a set name.
</Note>
