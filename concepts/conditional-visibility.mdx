title: "Conditional Visibility (Show If)"
description: "Show or hide a question, a section, or a whole page based on answers the respondent has already given — the operators, how to combine them, and the one direction a rule can't point."
---


A **Show If** rule (the `Show If` column in the Questions sheet) makes a row appear only when the
answers so far meet a condition — for example, *show "How many employees?" only when "Are you a
business?" = Yes*.

<Note>
  **The one rule to remember:** a Show If can depend on any answer the respondent has **already
  given** — on this page or any earlier one. What it cannot depend on is an answer they have not
  reached yet, because that rule could never fire.
</Note>

## Writing a rule

The easiest way is the **Show-If Builder** in the AutoSurvey sidebar (in Google Sheets, open the
**AutoSurvey** menu → sidebar). Pick the controlling question — it offers every question on this
screen or any earlier one — choose a condition, pick the value(s) from that question's own choices,
and it writes a valid rule into the cell.

The builder writes **one condition per rule**. To combine conditions across different questions,
type the rule yourself using the syntax below.

## Operators

| Operator | Meaning | Example |
| --- | --- | --- |
| `=` | equals | `Role__c = 'Manager'` |
| `!=` | not equals | `Status__c != 'Closed'` |
| `IN (…)` | matches any of | `Role__c IN ('Manager', 'Lead')` |
| `NOT IN (…)` | matches none of | `Region__c NOT IN ('US', 'CA')` |
| `ISBLANK(x)` | x has no answer | `ISBLANK(Comments__c)` |
| `ISNOTBLANK(x)` | x has an answer | `ISNOTBLANK(Email__c)` |
| `<` `<=` `>` `>=` | numeric comparison | `Score__c >= 8` |

A bare field name is shorthand for `= true` — handy for a checkbox: `Opted_In__c`.

Quote text values with single quotes; leave numbers and `true` / `false` unquoted.

<Warning>
  **The comparison operators are numeric.** They work on `Number`, `NPS`, `Star`, `Slider`,
  `Currency` and `Percent` questions. Point one at a text or choice question and the rule imports
  with a warning (`ORDERING_ON_NON_NUMERIC`) and then never fires for anyone. The Show-If Builder
  only offers them on numeric questions, which is the easiest way not to hit this.
</Warning>

## Combining conditions

Use `AND`, `OR`, `NOT` and parentheses, mixed however you need:

```text
Role__c = 'Manager' AND Region__c IN ('US', 'CA')
```

```text
(Role__c = 'Manager' OR Role__c = 'Lead') AND Score__c >= 8
```

```text
NOT ISBLANK(Comments__c) AND Opted_In__c
```

<Tip>
  To match several values of the **same** question, `IN (…)` is shorter and clearer than an `OR`
  chain — and it is what the Show-If Builder writes.
</Tip>

A rule can hold up to **50 conditions**. Nesting is capped well above anything readable; if you hit
either limit, the rule is almost certainly better split across a section.

## What a rule can be attached to

Show If is not only for questions. Put it on any row:

| Row | Effect |
| --- | --- |
| A **question** | Shows or hides that question |
| A **Section** | Shows or hides the section **and every question in it** |
| A **Screen** row | Shows or skips **the whole page** |
| A **Terminal Screen** row | Decides which respondents end the survey there — this is how you screen someone out |

<Warning>
  A section's rule cascades. A question inside a hidden section is hidden regardless of its own
  Show If — the two conditions combine, they don't compete. If a question needs to appear when its
  section doesn't, move it out of the section.
</Warning>

<Warning>
  **Don't mix different Show If rules across every row of a page.** If every row on a page is
  conditional and two or more **different** rules are in play, some answer combinations could leave
  the page with parts missing — or nothing at all — so the import stops with `SCREEN_MAY_BE_EMPTY`.
  Leave at least one thing on the page with no Show If — a heading, an instruction, or the question
  the page is really about.

  One shape is fine by design: when a page's conditional rows all share one **identical** rule (or
  the page has just one conditional row), the page shows or hides as a single unit — respondents
  whose answers hide it simply skip the page. That is the supported way to branch a whole page.
</Warning>

## Reactive on the same page

When a controlling question is on the **same page**, show/hide happens as the respondent types or
clicks — they don't have to move on for the follow-up to appear. This works for every question type,
including Long Text and Matrix.

When the controlling question is on an **earlier** page, the rule is evaluated when the later page
opens, which is the only moment it can be.

## When a rule is rejected

| What you did | What happens |
| --- | --- |
| Referenced an API name no question uses | `UNKNOWN_VISIBILITY_REFERENCE` — import stops |
| Pointed a question at itself | `SELF_REFERENCING_VISIBILITY` — import stops |
| Referenced an answer from a **later** page | `VISIBILITY_FORWARD_REFERENCE` — import stops |
| Contradicted a question against itself — like `Score__c > 5 AND Score__c < 3` | `SINGLE_FIELD_CONTRADICTION` — import stops |
| Built a loop — A controls B controls A | `DEPENDENCY_CYCLE` — warning |
| Compared a non-numeric question with `<` or `>` | `ORDERING_ON_NON_NUMERIC` — warning |
| Matched a choice value the Option Set no longer has | `STALE_CHOICE_LITERAL` — warning |

The contradiction check looks at one question at a time. A condition that can never be true because
of how **different** questions combine isn't caught — the survey imports, and that row simply never
shows.

<Note>
  A **warning** means the survey imports and then behaves in a way you probably didn't intend —
  usually a rule that silently never fires. They are worth reading. See
  [Troubleshooting](/support/troubleshooting).
</Note>

## When Show If isn't enough

Show If decides whether a row is *visible*. It does not decide where a respondent goes next. For
that, use a **Terminal Screen** with its own Show If — that ends the survey for the respondents who
match, and lets everyone else continue. See [Display Types](/concepts/display-types).
