---
title: "Import an Existing Survey"
description: "Bring a survey you already run in Typeform, Google Forms, SurveyMonkey or GetFeedback into AutoSurvey — paste its link, review what came across, and create the survey."
---


If you already run a survey somewhere else, you don't have to retype it. Paste its link and
AutoSurvey reads the questions, the choice lists and the screen structure, and shows you what it
found before the survey is created.

## What can be imported

| Source | How AutoSurvey reads it |
| --- | --- |
| **Typeform** | From the public link |
| **Google Forms** | From the published form link |
| **GetFeedback** | From the public link, or connected to your account for private surveys |
| **SurveyMonkey** | From the survey's public `/r/` link, or connected to your account for any other link |

<Note>
  **Only private imports need a connection.** A public link imports with no set-up at all, from
  **New Survey**. To import from your own GetFeedback or SurveyMonkey account, open a survey, pick
  **Populate questions…** or **Change questions…** from its **⋯** menu, then choose **Bring your
  survey**. That needs a one-time authorisation, and the permission sets are **SurveyMonkey API
  Access** and **GetFeedback API Access** — see
  [Installation & Permissions](/admin/installation-and-permissions).
</Note>

<Warning>
  Paste a **Qualtrics** or **Delighted** link and AutoSurvey will recognise which tool it is, but
  cannot import it — there's no importer for those yet. Uploading an export file (for example a
  Qualtrics `.qsf` file) is not supported either. For those, choose **Paste your questions** in
  [New Survey](/workflows/prompt-to-flow) and paste your question wording in.
</Warning>

## How it goes

<Steps>
  <Step title="Paste the link">
    Click **New Survey** and choose **Bring your survey**. Paste the link in **Survey link**.
    AutoSurvey names the tool it detected, for example **Detected: Google Forms**. Then click
    **Preview my survey**. Nothing is created yet.
  </Step>
  <Step title="Review what came across">
    The Review screen shows every question it found, each with the display type it will become.
    A matrix question shows as one row with its row count. The summary line totals the questions
    and screens. **List** shows the questions; **Preview** shows each screen as a read-only form.
    A notice calls out any rule that could not be written. If the survey has images, you choose
    which ones to copy into Salesforce.
  </Step>
  <Step title="Create">
    Set the **Title**, the **Workspace** and the **Survey ID**. Tick **I confirm I have the right to
    use this survey content in AutoSurvey** — only the question structure is imported, never
    responses. Then click **Create survey**. From there it is an ordinary AutoSurvey survey — edit
    it on the **Questions** tab, then release it.
  </Step>
</Steps>

<Tip>
  **Read the Review screen properly.** It is the cheapest moment to notice a question that came
  across as the wrong type. For an imported survey you cannot change or remove questions there —
  you do that after you create the survey, on the **Questions** tab, where the display type is a
  picker rather than a re-import.
</Tip>

## Branching comes across too

Conditional logic is translated, not discarded. A rule that says *"show this only if they picked
Yes"* in the original becomes a **Show If** rule in AutoSurvey, rewritten to point at the API names
your imported questions ended up with.

Jump-to-end logic translates as well — a Typeform thank-you jump or a Google Forms "submit form"
branch becomes a [Terminal Screen](/concepts/display-types), so respondents who should finish early
still do.

<Note>
  A rule AutoSurvey could not translate cleanly is **reported on the Review screen** under **Not
  every rule could be written**, not dropped quietly. Read the notices before you create the
  survey — that is where you find out a branch needs rebuilding by hand.
</Note>

## What happens to the layout

AutoSurvey matches how the original *felt*:

* **Typeform** and **GetFeedback** show one question per screen, so an import from either defaults
  to that layout.
* **Google Forms** groups questions into pages, so its pages become your screens.

You can change it afterwards on the **Questions** tab, or in the `Screen` column of the sheet. See
[The Questions Sheet](/concepts/questions-sheet).

## What to check after importing

An import gets you the content; it doesn't get you a finished survey. Worth a pass over:

| | |
| --- | --- |
| **Display types** | Every tool has types with no exact match. Check the type on each Review row, and the [Display Types](/concepts/display-types) page for what's available |
| **Show If rules** | Branching *is* imported, but check it. A rule that couldn't be translated cleanly is reported on the Review screen rather than dropped silently — see [Conditional Visibility](/concepts/conditional-visibility) |
| **Metric Type** | Mark your NPS/CSAT/CES question so scoring and [CX Analytics](/concepts/the-autosurvey-app) work |
| **Design** | The import brings the source survey's own look where it can, so the Review screen has no Look choice. Check it on the Design page — see [Themes & Design](/concepts/themes-and-design) |

<Note>
  **Responses don't come with it.** Importing brings the *survey*, not the answers people already
  gave it. Export those from the original tool if you need them.
</Note>
