title: "Installation & Permissions"
description: "Which permission set group to give each person: admin, author, operator, reporting user, support user and respondent. Also the sets for guests, members and each optional feature."
---

Each person needs the correct access before the person can open AutoSurvey. AutoSurvey installs a
permission set group for each role. Give each person one role. A person can hold two roles, for
example Author and Reporting.

## The role groups

| Assign this group | To | What the person can do | What the person cannot do |
| --- | --- | --- | --- |
| **AutoSurvey Full Admin** | The person who sets up and runs AutoSurvey | Open Setup and change org settings. Create, design and edit surveys. Release, publish, send, assign, pause, close and retire. Read results, answers and who answered. Export raw responses. | Reveal masked answers. Delete a submission in the app (that needs the **Delete Submission** permission). Note: the group grants the Salesforce object permission Delete on Survey Submission and Survey Answer, so a full admin can delete those records outside the app, for example in a list view or with the API. |
| **AutoSurvey Author** | The person who writes surveys | Open the Workspace. Create, design and edit surveys. Save drafts, themes and translations. Generate questions with AI. | Release, publish or send. Read submissions or answers. Open Setup. |
| **AutoSurvey Operator** | The person who runs surveys | Open the Workspace to read. Release, publish, send, assign, pause, close and retire. Mark data quality. Read the Results totals. | Edit a survey. Read individual answers. Open Setup. |
| **AutoSurvey Support** | A support user who fixes survey data | Read and fix data in every survey. Reveal masked answers. Delete submissions. Export raw responses. Edit, release, publish, send, pause, close and retire surveys. | Open Setup. Change org settings. |
| **AutoSurvey Reporting** | An analyst who reads results | Reports and list views in every survey, and CX Analytics. | Change a record. Open the Workspace. Open Setup. See who answered. |
| **AutoSurvey Respondent** | Internal staff who answer surveys | See the **My Surveys** inbox. Open and submit a survey that is assigned to them. | Open the Workspace. Read results. Open Setup. |

- At least one person must hold **AutoSurvey Full Admin**.
- **AutoSurvey Support** can read and delete every response. Give it to a small number of trusted users.
- To show who answered to a reporting user, add **AutoSurvey Raw Response Access**.
- To release, an operator also needs the System Administrator profile or the
  `AutoSurvey_Admin_Salesforce_Permissions` set that your org makes. A Salesforce Platform user cannot
  release.

<Warning>
Assign the group, not the sets in it. For example, **My Surveys** alone shows a **Take survey**
button that cannot open the survey.
</Warning>

## Who assigns the groups

A System Administrator assigns each group in **Setup → Permission Set Groups**. Setup Home shows the
roles and checks your access. It does not assign a role. See
[Permission Sets](/admin/setup#permission-sets).

There are three exceptions. None of them gives you a role.

- **Complete Setup** assigns the two sign-in sets, **Self Org Access** and **Self Org JWT Access**, to
  the admin who clicks it. It also gives the AutoSurvey admins the sets of the features that are on by
  default.
- **Grant sign-in access** on the **AutoSurvey Sign-In** row assigns **Self Org Access** to the user
  who clicks it.
- A switch on a card in **Optional Capabilities** gives the set of the feature to the AutoSurvey admins.

## The AutoSurvey server connection

The set **PBO Service Access** (`atsv__PBO_Service_Access`) lets a user reach the AutoSurvey server.
Without it, the **AutoSurvey Server Connection** check fails and names the set. The Full Admin, Author,
Operator and Support groups contain it. The Reporting and Respondent groups do not. The set
**AutoSurvey Admin** alone does not give this access.

## People who release surveys

AutoSurvey signs in to your org as the user who releases a survey, to add the reporting fields of
the survey.

1. The user holds **Self Org Access**. The Full Admin, Operator and Support groups contain it.
2. The user clicks **Authorize AutoSurvey** one time on the **AutoSurvey Sign-In** row of Setup Home,
   then clicks **Allow**. Until then, the first release fails. See
   [Setup Home](/admin/setup#self-org-sign-in).

You do not need to assign **Self Org JWT Access**. It is deprecated and gives no access.

## Respondents outside your staff

| Who | Assign |
| --- | --- |
| Members who are signed in to your Experience site | **Member Runtime** |
| All people with the link, with no login | **AutoSurvey Guest Access**, on the guest user of the site |
| People who open a booking link | **Slot Booking Guest Access**, on the guest user of the site, only when **Program Slot Booking** is on |

<Note>
Guest access belongs to the Experience site, not to a person. If a public survey does not open, check
the permissions of the guest user first. The **Public link** row on the Send tab checks them for you.
</Note>

## Sets for one task

| Permission set | What it gives |
| --- | --- |
| **AutoSurvey Raw Response Access** | Each response with who answered, the raw-response reports, and raw CSV and ZIP exports. |
| **AutoSurvey List View Access** | A user can make private list views on objects that the user can already see. |
| **OpenAI BYOK Access** and **Anthropic BYOK Access** | Use of your own AI provider key. |
| **GetFeedback API Access** | Import from a private GetFeedback account. |
| **SurveyMonkey API Access** | Import from a private SurveyMonkey account. |

## Sets for the optional features

Each optional feature has a card in **Setup**, **Optional Capabilities**. See
[Optional Capabilities](/admin/setup#optional-capabilities).

- The set in the column "The switch gives" goes to the AutoSurvey admins when you turn the feature on.
  If you turn the feature off, AutoSurvey removes that set from every user. You can also assign
  **AutoSurvey Shield Admin** and **AutoSurvey Rewards Manager** to other people. Do not assign the
  other sets in this column by hand.
- An admin assigns the sets in the column "An admin assigns" to the people who need them.

| Feature card | The switch gives | An admin assigns |
| --- | --- | --- |
| **Text messages** | None | **AutoSurvey Text Sending**, to the one sending user, on the **Text Messaging** tab. **AutoSurvey Text Phone Viewer**, to see full phone numbers. |
| **Multi-language surveys** | **AutoSurvey Multi-language** | None |
| **Program Slot Booking** | **AutoSurvey Slot Booking Admin**: the tab only | **Slot Booking Staff**, to the staff who run sessions. **Slot Booking Notice Sender**, to one integration user, for live booking notices. |
| **Participant Request Center** | The group **Participant Request Center (feature)**: the two template sets, and no participant data | **Participant Requests User**, to case workers. **Document Request Author** and **Document Request Template Publisher**, to other staff who write or activate templates. |
| **Fraud & Quality Shield** | **AutoSurvey Shield Admin**: policies, rules and bindings | **AutoSurvey Shield Reviewer**: approve or reject a held submission |
| **Shield Rewards** | **AutoSurvey Rewards Manager**: the connection, reward rules, budgets and the approval mode | **AutoSurvey Rewards Approver**: approve reward spend. **AutoSurvey Rewards Corrector**: fix a failed or misdirected reward. **AutoSurvey Rewards Worker**: the integration user only. |
| **Change with AI** | **AutoSurvey Change with AI** | None |
| **AI images** | **AutoSurvey AI Images** | None |
| **Record writes** | **AutoSurvey Record Writes** | None |
| **AI you control** | **AutoSurvey AI You Control** | None |
| **Intake to Record** | **AutoSurvey Intake to Record** | None |
| **Calculated values** | **AutoSurvey Calculated Values** | None |
| **AI reads answers** | **AutoSurvey AI Reads Answers** | None |
| **Workspace environments** | **AutoSurvey Workspace Environments** | None |
| **Standard questions** | **AutoSurvey Standard Questions** | None |

## Custom permissions for one action

| Custom permission | Lets a person |
| --- | --- |
| **Publish Survey** | Make a release live. |
| **Close Survey**, **Pause Collection**, **Retire Survey** | Change the state of a survey. |
| **Send Invitations**, **Assign Recipients** | Send a survey and choose who gets it. |
| **Send Text Invitations** | Send a survey by text message. The person also needs **Send Invitations**. |
| **Reminders Live** | Let reminder schedules send email. An admin must also turn on **Send reminder email for real** in AutoSurvey Settings. Until then, reminders run as a dry run. |
| **Choose AI Models** | Choose the AI model for each step of one survey build. It does not change the tiers of the org. |
| **Delete Submission** | Delete a response. |
| **Reveal Masked Answers** | See the contents of a masked answer. |
| **Mark Data Quality** | Mark the data quality of a response. |
| **AutoSurvey: Raw Response Access** | Read individual response data. |
| **Deploy Surveys** | Run metadata deploy operations. |

Use a custom permission to give a person one action, for example a coordinator who can send
invitations and cannot publish.

## Sets that you do not assign

- The sets in a role group. Assign the group.
- **Setup Bootstrap**, except for the person who runs the first setup. It is the smallest access that
  opens Setup Home.
- **Default Admin Field Access**, **Config Version Fields Access**, **AutoSurvey Flat Object Access**
  and **Self Org JWT Access**. They are deprecated and give nothing new.
- **AutoSurvey SuiteKey Reporting TEMPLATE**. AutoSurvey copies it for each survey.
- **Participant Request Center (feature)**. The Setup Home switch assigns and removes this group.

<Note>
AutoSurvey is a managed package. In Setup, its API names start with `atsv__`, for example
`atsv__AutoSurvey_Admin`. Labels do not show the prefix.
</Note>
